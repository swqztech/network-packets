# 第一课：什么是网络包？

## 1. 从发一句话开始

你在浏览器输入网址、点发送，本质上是：**应用把字节交给操作系统，操作系统再一节一节贴上「地址标签」，交给网卡发出去**。

路上每一个「带标签的小块」就是我们常说的 **网络包（packet）** 或其链路层形态 **帧（frame）**。口语里经常都叫「包」。

```
[你的 HTTP 请求字节]
        ↓ 套上 TCP 头（端口、序号…）
[TCP 段]
        ↓ 套上 IP 头（源/目的 IP…）
[IP 包]
        ↓ 套上以太网头（MAC 地址…）
[以太网帧] → 网线 / Wi‑Fi 发出去
```

这叫 **封装（encapsulation）**：每层只关心自己的「头 + 交给我的载荷」。

## 2. 为什么分层？

| 层（TCP/IP 常见说法） |  roughly 干什么 | 本课 demo 涉及 |
|----------------------|-----------------|----------------|
| 应用层 | HTTP、DNS 等语义 | 载荷里的 ASCII 文本 |
| 传输层 | 端到端：端口、可靠/不可靠 | **TCP 头** |
| 网络层 | 主机到主机：IP 寻址 | **IP 头** |
| 链路层 | 同一网段：MAC | **以太网头**（示例里有一帧） |

分层的好处：**换网线/Wi‑Fi（链路层）不必改你的网页逻辑（应用层）**。

## 3. 包头里到底有什么？（先记轮廓）

不必第一课就背满每位，知道「有哪些字段、干什么」即可：

- **以太网**：目的 MAC、源 MAC、类型（例如 `0x0800` = 里面是 IPv4）
- **IPv4**：版本、头长、总长度、**源 IP / 目的 IP**、协议号（6=TCP，17=UDP）
- **TCP**：**源端口 / 目的端口**、序号、标志位（SYN/ACK…）、窗口等

抓包工具（Wireshark）看到的十六进制，就是这些东西连在一起。

## 4. 本课代码在做什么？

1. **`parse_sample_frame.py`**  
   读入一段 **真实的十六进制抓包样本**（简化的一帧以太网 + IPv4 + TCP），用 Python 按字节 **解析并打印** 各层字段。  
   **不需要管理员权限、不抓 live 网卡**，适合安静地在本地理解结构。

2. **`send_one_udp.py`**（可选）  
   向本机 `127.0.0.1` 发一个 UDP 小包，让你看到：**应用只写 payload，内核负责封 IP/UDP**。若你装了 Wireshark 并过滤 `udp.port==54321`，可同时观察（第一课不强制）。

## 5. 怎么运行

```bash
cd lesson-01-什么是网络包
python parse_sample_frame.py
# 可选：
python send_one_udp.py
```

## 6. 小测验（自检）

1. 「帧」和「包」在口语里常混用，严格说以太网那一层常叫 **帧**，IP 层叫 **包**，对吗？  
2. 看到 IP 头里 `protocol = 6`，下层传输协议是？  
3. 如果只有 IP 没有 TCP，网页还能用 HTTPS 吗？为什么？

<details>
<summary>参考答案</summary>

1. 大致对：链路层多称帧，网络层称包；再往上有的书叫「段」（TCP）。  
2. TCP。  
3. 不能。HTTPS 运行在 TCP 之上，需要 TCP 提供可靠字节流与端口。

</details>
