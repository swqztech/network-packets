# 第三课：TCP、UDP 与端口

IP 把包送到**哪台机器**；传输层用 **端口号** 把数据交给**哪一个进程**（浏览器、游戏、DNS…）。本课对比 **TCP** 与 **UDP**，并走一遍 **三次握手**。

## 1. 端口：一台电脑上的「房间号」

IPv4 地址像大楼门牌；**端口 0–65535** 像房间号。

| 范围 | 常见用途 |
|------|----------|
| 0–1023 | 熟知端口（需管理员权限绑定，如 80/443/53） |
| 1024–49151 | 注册端口 |
| 49152–65535 | 临时端口（客户端常用于出站连接） |

同一时刻可有多条连接：`(源IP, 源端口, 目的IP, 目的端口)` 四元组区分 **TCP 连接**。

## 2. UDP：有头就收，不保证顺序与重传

```
 0      7 8     15 16    23 24    31
+--------+--------+--------+--------+
|   源端口        |   目的端口       |
+--------+--------+--------+--------+
|   长度          |   校验和         |
+--------+--------+--------+--------+
|          载荷（任意长度）           |
```

- **无连接**：发即走，内核不维护「会话状态」。
- **不保证** 必达、不乱序、不重复（应用自己处理或不管）。
- 适合：**DNS 查询、直播/游戏、VoIP** 等可容忍丢包或自己纠错的场景。

运行 `udp_local_demo.py`：本机 UDP 一发一收，亲眼看到只有「端口 + 载荷」。

## 3. TCP：可靠字节流 + 连接

TCP 头（至少 20 字节）核心字段：

| 字段 | 作用 |
|------|------|
| 源/目的端口 | 同 UDP |
| 序号 Seq | 字节流位置，用于排序与重传 |
| 确认号 Ack | 期望对方下一个字节序号（ACK 有效时） |
| 标志位 | SYN 建连、ACK 确认、FIN 结束、RST 重置… |
| 窗口 | 流量控制 |

- **面向连接**：先握手，再传数据，最后挥手。
- **可靠、有序**（对应用呈现连续字节流）。
- 适合：**HTTP/HTTPS、邮件、文件下载** 等不能乱丢数据的场景。

`parse_transport.py` 会解析本课样本：**SYN**、**SYN+ACK**、**UDP**。

## 4. 三次握手（建立连接）

```
客户端                                 服务端
   |  SYN  seq=x                       |
   |---------------------------------->|
   |           SYN+ACK  seq=y, ack=x+1 |
   |<----------------------------------|
   |  ACK  ack=y+1                     |
   |---------------------------------->|
   |        此后可传 HTTP 等数据        |
```

要点：

1. **SYN** 消耗一个序号（故第二次要 `ack=x+1`）。
2. 双方各自选好 **ISN（初始序号）**，真实值随机化，防 spoof。
3. 只有第三次 **ACK** 到后，服务端才常认为连接 **ESTABLISHED**。

运行 `tcp_handshake_walkthrough.py`：用与本课一致的序号打印三条「逻辑包」（不真正连外网）。

## 5. TCP vs UDP 怎么选？

| | TCP | UDP |
|---|-----|-----|
| 连接 | 要握手 | 无 |
| 可靠 | 内核重传、排序 | 不保证 |
| 开销 | 更大 | 更小 |
| 典型 | 网页、API | DNS、QUIC 底层仍复杂，但 DNS 本身多用 UDP |

**同走 IP**：第二课的 TTL、路由对两者一样；差别在主机收到后交给 TCP 还是 UDP 模块。
